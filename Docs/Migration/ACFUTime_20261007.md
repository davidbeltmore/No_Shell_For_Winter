## Compatibility boundaries

- The native actor is the single clock returned by DaySequenceSubsystem in the tested playable worlds. ACF time text, apparent time used by routines, and the retained HUD/calendar agree to less than one calendar second. The project owns the persistent day number, three phase labels and existing presentation; native DaySequence owns advancement. There is no second calendar integrator.
- A 24-hour day remains 1,800 simulation seconds. Training and needs consume simulation DeltaSeconds through the existing conversion; effects/statuses retain simulation-second durations. Global dilation controls all of these once. The final legacy probe measured training/calendar error `2.0663e-8` calendar hours and status/calendar error `1.4305e-6` simulation seconds. Both freeze exactly during pause; the 0.4-hour book completes and the 30-second status expires.

The optional vendor rest widget has not been substituted into the player's UI. Existing sample time-manager actors and optional demo maps were not rewritten.
- Existing normal-world travel and ALS saves are tested, including the unchanged legacy saved fields. This does not add a new game lifecycle, multiplayer certification or an exhaustive death/respawn test.
